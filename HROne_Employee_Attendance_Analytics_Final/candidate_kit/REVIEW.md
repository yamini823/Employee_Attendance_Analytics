# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | Startup / Lifespan | No database indexes are created during application startup. | Concurrency tests on employee creation or punch-in fail to prevent duplicates; explain plans reveal `COLLSCAN` on ~100k documents. | Added a FastAPI `lifespan` handler executing `create_indexes()` to idempotently build unique and compound indexes. |
| 2 | `health()` / L72-75 | `GET /health` unconditionally returns `{"status": "ok"}` without pinging MongoDB. | When MongoDB is stopped or connection drops, the endpoint still returns HTTP 200 instead of 503. | Added `client.admin.command("ping")` inside a try-except block; returns HTTP 503 if MongoDB fails to respond. |
| 3 | `create_employee()` / L78-86 | Check-then-insert race condition (`find_one` followed by `insert_one`). | Concurrent duplicate `POST /employees` requests both pass `find_one` and insert duplicates. | Backed `emp_code` with a MongoDB unique index and handle `DuplicateKeyError` to return HTTP 409. |
| 4 | `EmployeeIn` / L53-61 | Insufficient Pydantic validation: allows arbitrary `emp_code` strings, invalid emails, unconstrained string lengths, and identical shift times. | Submitting `emp_code="ABC"`, malformed emails, or `shift_start == shift_end` ("09:30") returns 201 instead of 422. | Enforced regex pattern `^EMP\d{4,6}$`, email format, length bounds, and a model validator ensuring `shift_start != shift_end`. |
| 5 | `create_employee()` / L82-85 | `created_at` timestamp is set using naive local `datetime.now()` and returned as an unformatted timestamp. | OpenAPI contract requires `created_at` to be an int64 epoch millisecond timestamp; client received an ISO string or object. | Stored UTC datetime truncated to seconds in MongoDB and serialized to integer epoch milliseconds in API responses. |
| 6 | `list_employees()` / L93 | Off-by-one pagination skip: `skip = page * page_size`. For page 1, `skip = 20`. | `GET /employees?page=1` omits the first 20 employees entirely. | Corrected skip formula to `(page - 1) * page_size`. |
| 7 | `list_employees()` / L94 | Total count ignores filter: `total = db.employees.count_documents({})`. | `GET /employees?department=Sales` reports the total collection count instead of the filtered count. | Passed filter query `q` into `db.employees.count_documents(q)`. |
| 8 | `list_employees()` / L95 | Missing query sorting. | Results return in non-deterministic natural MongoDB insertion order rather than `emp_code` ascending. | Added `.sort("emp_code", 1)` to the MongoDB query cursor. |
| 9 | `compute_late_minutes()` / L33-37 | Replaced hour/minute on `punch_in` without converting to IST; checked `minutes > 10` after integer floor division. | For punch-in at 09:40:01 (10 min 1 sec after 09:30), `601 // 60` is 10, so `10 > 10` evaluates to False, yielding 0 late minutes instead of 10. | Converted instant to IST, verified if `(punch_in_ist - shift_start_dt).total_seconds() > 600`, and calculated `int(diff_sec // 60)`. |
| 10 | `compute_work_hours()` / L40-42 | Used Python's built-in `round()`, which applies banker's rounding (`ROUND_HALF_EVEN`). | Borderline durations (e.g. 4.495 or 8.125 hours) round to even numbers rather than half-up (R4). | Implemented rounding via `decimal.Decimal` with `ROUND_HALF_UP`. |
| 11 | `compute_overtime()` / L44-47 | Returned all positive minutes without enforcing the 30-minute minimum threshold; miscalculated overnight shift end date. | Punch-out 15 minutes past shift end reported 15 minutes overtime (R3 requires 0); overnight shifts miscalculated end time by 24 hours. | Enforced `>= 1800` seconds threshold; incremented shift end date by 1 day when `shift_end <= shift_start`. |
| 12 | `punch_in()` / L100-105 | Does not verify employee existence before accessing shift parameters. | Punching in with a nonexistent `emp_code` caused `TypeError: 'NoneType' object is not subscriptable` (HTTP 500). | Checked employee existence with `find_one()` and raised HTTP 404 when missing. |
| 13 | `punch_in()` / L102-104 | Date attribution `ts.date().isoformat()` used server local date and ignored overnight shifts (R1). | A punch-in before `shift_end` in an overnight shift (e.g., 05:30 on 22:00-06:00 shift) was attributed to the current day instead of the previous day. | Implemented `get_attendance_date()` converting UTC to IST and attributing pre-shift-end overnight punches to `date - 1 day`. |
| 14 | `punch_in()` / L104-118 | Check-then-insert race condition for punch-in uniqueness. | Concurrent identical punch-ins both passed `find_one` and inserted duplicate records for the same employee and date. | Enforced compound unique index `{"emp_code": 1, "date": 1}` and caught `DuplicateKeyError` to return HTTP 409. |
| 15 | `punch_in()` & `list_attendance()` / L119, L149 | Injected forbidden internal `id: str(res.inserted_id)` into response body. | Violates OpenAPI contract for `AttendanceRecord`, which has no `id` property. | Stripped MongoDB internal `_id` and prevented adding synthetic `id` field. |
| 16 | `list_attendance()` / L144-147 | Fetched entire collection into Python memory (`list(find(q))`) and sorted in Python. | High memory consumption and severe latency degradation on 100,000+ documents. | Delegated sorting, pagination, and counting natively to MongoDB cursor `.sort()`, `.skip()`, `.limit()`. |
| 17 | `list_attendance()` / L125-132 | Missing validation for `date_from > date_to`. | Querying `date_from=2026-07-10&date_to=2026-07-01` returned an empty list instead of HTTP 422. | Added explicit date validation raising HTTP 422 when `date_from > date_to`. |
| 18 | Whole-second truncation / R1 | Instant fields accepted fractional seconds and preserved microseconds. | Microsecond differences caused inconsistent duration and rounding calculations. | Implemented whole-second truncation on all input instants (`epoch_ms // 1000 * 1000`) before calculations and storage. |

### Examined and Decided Was Not a Defect

1. **Storing Calendar Dates as ISO Strings (`"YYYY-MM-DD"`)**:
   - Examined whether `date` should be stored as a BSON Date or string. Confirmed by `DATA_MODEL.md` that dates are intentionally plain strings in IST to prevent arbitrary time-zone shifting or forced timestamp conversion.
2. **Storing Precomputed Derived Fields (`work_hours`, `late_minutes`, `overtime_minutes`, `half_day`)**:
   - Examined whether analytics should recompute metrics on the fly from punch timestamps. Confirmed by `DATA_MODEL.md` and `openapi.yaml` that stored derived fields are authoritative and must be read directly by analytics pipelines.
3. **Absence of Synthetic IDs on Attendance Records**:
   - Examined whether attendance documents need an `id` field. Confirmed that records are strictly natural-keyed by `(emp_code, date)` and exposing an `id` violates the OpenAPI schema.
